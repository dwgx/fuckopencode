它到底解决了什么

每一条都是真实撞过的上游报错，不是假想的兼容性问题。左边是直连 DeepSeek 会遇到的，右边是网关做的事。

特性

转换核心是零依赖纯函数，服务层该有的生产防护都在。

双向协议转换

OpenAI Chat Completions 与 Anthropic Messages 互转：消息交替规整、tool_use/tool_result id FIFO 配对、system 抽取到顶层字段。

零运行时依赖

纯 TypeScript strict 模式、零 any、Node 原生 http。核心转换逻辑是可独立复用的纯函数。

JSON mode 真实现

response_format 经强制工具落地，响应和流式都转回 content，finish_reason=stop 与 OpenAI 原生对齐。

流式逐事件映射

Anthropic SSE 全事件转 OpenAI chunk：reasoning_content 增量、usage 独立尾 chunk、背压、收尾一定补 [DONE]。

安全默认 fail-closed

常量时间鉴权；未配 key 且未显式放行时一律拒绝，放行也只在绑定回环地址时生效。

输入防护

结构校验与长度上限、SSRF 判定（含 IPv6 与 IPv4-mapped）、注入启发式检测、内部错误不外泄。

快速开始

一条命令起服务，OpenAI 和 Anthropic 两种客户端都能直接调。

# 安装并启动（把 ANTHROPIC_API_KEY 换成你的上游 key）
npm install && npm run build
API_KEYS=demo-key ANTHROPIC_API_KEY=sk-xxx npm run serve

# OpenAI 客户端
curl http://127.0.0.1:8787/v1/chat/completions \
  -H "Authorization: Bearer demo-key" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-4o","messages":[{"role":"user","content":"1+1=?"}]}'

# Claude Code 直接指过来
ANTHROPIC_BASE_URL=http://127.0.0.1:8787 \
ANTHROPIC_AUTH_TOKEN=demo-key \
ANTHROPIC_DEFAULT_SONNET_MODEL=deepseek-v4-flash \
claude

端点

同时暴露两套协议，共用一个上游。

路径协议说明
POST /v1/chat/completionsOpenAI协议转换 → DeepSeek，流式/非流式
POST /v1/messagesAnthropic直通 + DeepSeek 归一化，流式/非流式
POST /v1/messages/count_tokensAnthropicClaude Code 记账
GET /v1/modelsOpenAI模型发现
GET /healthz—健康检查，无需鉴权

两条路径

入口协议不同，走的代码路径也完全不同。

/v1/messages 校验→ DeepSeek 归一化→ 注入扫描→ 转发→ 按需过滤 thinking 流
/v1/chat/completions 校验→ 注入扫描→ 协议转换→ system 护栏→ 转发→ 转回 OpenAI
直通不等于裸转发。 /v1/messages 收到的已经是 Anthropic 协议，但仍要做 DeepSeek 归一化才能被上游接受， 响应侧则在关闭思考时剥掉多余的 thinking 事件。
